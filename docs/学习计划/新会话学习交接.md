## 1. 学习者情况与目标

- 默认使用中文。
- 学习者有 Python 基础，目标是 AI 全栈应用工程师岗位。
- 目标不是背源码，而是能运行、能解释、能排障、能说明取舍，并应对面试官连续追问。
- 不包装不存在的生产能力；计划中的优化必须明确说成“尚未实现”。
- 类名、函数名和配置键可以保留英文，但第一次出现时必须先用中文解释它解决什么问题。

## 2. 必须遵守的学习方式

### 第一遍：直接详细讲解

当前处于第一遍学习。讲解者应直接给出完整内容，不要每讲一个知识点就反问学习者。

每个主题应包含：

1. 先记住的一条中文链路。
2. 它解决什么问题。
3. 为什么这样设计。
4. 一个具体例子。
5. 当前项目实际怎么实现。
6. 方案的代价与替代方案。
7. 常见错误说法。
8. 面试标准表达。
9. 当前项目的诚实边界。

第一遍允许在一个完整章节讲完后给出“下一节是什么”，但不要要求学习者现场回答。

### 第二遍：模拟面试

“第二阶段学习”仍属于第一遍详细讲解，不等于“第二遍模拟面试”。只有全部计划阶段的知识讲完后，才进入第二遍：

- 学习者先用自己的话回答。
- 讲解者纠正术语、因果和事实边界。
- 面试官连续追问。
- 不要求逐字背标准答案。

## 7. 当前不能说错的关键事实

1. DeepSearcher 是项目；DeepSearch 是查询策略。
2. 默认查询先由 RAGRouter 选择 DeepSearch 或 ChainOfRAG，不是默认走 NaiveRAG。
3. Chunk 是向量化和检索单元。
4. overlap 缓解切分边界；`wider_text` 补充生成上下文。
5. `1500/100` 是默认切分参数，没有评测证明最优。
6. 相同维度不代表不同 Embedding 模型兼容。
7. 当前默认 L2 是距离，越小越近。
8. Milvus 的 `score` 字段当前实际承载 distance。
9. 空结果也可能是系统失败。
10. LLM 路由输出必须校验。
11. DeepSearch 的 Rerank 更接近逐条 YES/NO 过滤。
12. DeepSearch 在 `max_iter=1` 时不会执行反思。
13. ChainOfRAG 默认关闭 early stopping，因此默认没有充分性反思。
14. Trace 是应用执行事件，不是模型内部思维链。
15. 当前 ChainOfRAG 不是 CoRAG 论文的完整复现。
16. 产品问答已经通过 POST + SSE 增量返回安全阶段；旧 `/console` 仍保留 POST JSON Trace 兼容链路，GET 查询已移除。
17. 仓库已有当前业务黄金集：3 份固定 PDF、72 题，覆盖跨文档、无答案、声明级引用和 12 题多轮上下文；
    真实 Dense/BM25/Hybrid 与代表性 Agent 回答基线均已落盘。
18. 当前配置仍是 Dense-only，Hybrid 只是已有代码分支。
19. 代理总体延迟没有拆成 RAG 阶段 Span，180 秒超时也不是 SLO。
20. `consume_token` 主要是 LLM 总 Token，不是精确账单。
21. 同步路由在线程池运行，不等于端到端异步或生产高并发。
22. BFF 校验不是最终安全边界，Collection 名称也不是租户权限。
23. FastAPI BackgroundTasks 不是持久化分布式任务队列。
24. 历史测试数字只用于对应阶段；当前自动化数字必须引用最近一次验证记录，且不能外推成容量或质量 SLO。
25. 当前默认前端入口是 `App.tsx` 产品工作台，包含知识库、持久化对话、文档状态和引用抽屉；旧学习控制台保留在 `/console`。
26. 产品上传走 multipart 和 `/api/knowledge-bases/{id}/documents`；Base64 `/api/ingest` 只属于旧学习控制台。
27. 产品工作台用 TanStack Query 管服务端状态，用 fetch ReadableStream 消费 SSE，并用
    AbortController 停止回答；断线后核心任务协作取消并释放 runtime lease。
28. 核心和 BFF 错误统一包含稳定 code、安全 message、request_id、retryable；核心已有服务令牌、
    租户/Collection ACL、每进程查询限流与可信 CORS 白名单，但仍没有最终用户 RBAC 和分布式配额。
29. 当前工作台只适合作为绑定 `127.0.0.1` 的单用户本地应用；安全响应头不等于登录或 RBAC，
    在身份、Workspace 归属和资源级权限落地前不能直接对局域网或公网开放。
30. 工作台默认拒绝非 loopback Host 和跨站写请求；反向代理部署必须显式配置可信 Host 与公开
    Origin，不能依赖 CORS 或资源 ID 代替最终用户授权。
31. 历史对话固定使用创建时绑定的知识库，不随全局当前知识库切换；顶栏和恢复入口必须依据
    对话知识库，不能用全局 `is_current` 冒充对话上下文。
32. 模态框的 `aria-modal` 不会自动提供焦点闭环；工作台已显式约束 Tab、支持 Esc、恢复触发点，
    并通过 skip link 允许键盘用户绕过重复侧栏导航。
33. 桌面端引用栏默认展开，`820px` 以下默认关闭；移动端按需打开后是模态抽屉，不应在进入历史
    对话时覆盖回答，也不能只靠 CSS 覆盖层代替焦点闭环和背景滚动锁定。
34. 引用开关必须同时表达是否可用、是否展开和受控区域；视觉表格不能只靠网格排版，动态状态也
    不能只靠颜色。当前工作台已补齐这些基础语义和定向对比度/目标尺寸验证，但未做完整辅助技术矩阵。
35. 连续追问发送当前问题和结构化历史，不再拼接历史文本；只有成功用户消息和 grounded/
    fully_grounded 助手回答进入有界历史，失败或部分支持回答不会作为可信助手上下文。
36. 多轮改写只能解释指代和省略，不能改变 Collection ACL 或联网开关；格式错误、模型失败和不合规
    话题切换输出都回退当前问题。
37. Trace v4 的声明级引用会拒绝不存在的 Evidence 编号并区分充分、部分、冲突和不足；它不是独立
    语义蕴含裁判，仍要看金标引用指标与人工抽查。模型生成时使用的有界 `wider_text` 会按同一
    Evidence 编号进入 Grounding；前端保留原始 Markdown/代码，再附加可展开的逐条核验区。
