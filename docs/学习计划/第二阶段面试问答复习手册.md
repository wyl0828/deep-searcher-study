## 一、FastAPI 与后端数据流高频题

### 1. 一次查询请求如何从 FastAPI 进入 DeepSearcher？

**标准回答：**

`GET /query/` 先由 FastAPI/Pydantic 解析 `original_query`、`max_iter` 和 `include_trace`。入口随后调用 `online_query.query()` 或 `query_with_trace()`，从 `deepsearcher.configuration` 读取当前全局 RAGRouter。RAGRouter 先选择 DeepSearch 或 ChainOfRAG，被选中的 Agent 再完成 Collection 路由、Embedding、Milvus 检索和答案生成。入口最终只返回答案、Token 和可选 Trace，不返回检索结果列表。

### 2. FastAPI 的 `def` 和 `async def` 有什么区别？当前项目属于哪一种？

**标准回答：**

同步 `def` 路由通常由 FastAPI 在线程池执行，不会直接占住事件循环；`async def` 在事件循环上执行，适合内部使用真正异步并可 `await` 的 I/O。当前四个业务接口都是 `def`，底层 LLM、Embedding 和 Milvus 调用也是同步的。它能用线程处理多个请求，但每个长调用都会占用有限工作线程。只把签名改成 `async def` 反而可能直接阻塞事件循环，必须逐层异步化或使用受控线程池、超时和并发上限。

### 3. `/load-files/` 为什么不能直接理解为浏览器文件上传？

**标准回答：**

它接收的是 JSON 中的后端文件系统路径，随后由服务进程读取该路径。远程浏览器本机路径对服务器不可见，接口也没有接收 multipart 文件字节。因此当前前端需要本地代理把浏览器文件保存为后端可见的临时文件，再调用该入口。生产中小文件可用 multipart，大文件更适合对象存储直传加异步任务。

### 4. 当前配置切换为什么不适合并发和多 worker？

**标准回答：**

`/set-provider-config/` 修改当前进程内存中的 Configuration，并调用 `init_config()` 重建模块级 LLM、Embedding、VectorDB 和 Agent。它没有锁、配置版本和资源回收协议，并发请求可能暂时使用不同代际对象；多个 Uvicorn worker 又是独立进程，内存状态不会自动同步。生产方案应使用版本化配置发布、依赖注入和请求级上下文，让旧请求自然结束后再回收旧实例。

### 5. 为什么不能把所有业务异常都返回 500？

**标准回答：**

500 应表示未预期的服务内部错误。文件不存在、参数语义错误、上游限流、依赖不可用和超时需要不同状态及稳定错误码，否则客户端无法判断是修改请求、重试还是稍后再试。当前入口还直接返回 `str(e)`，可能泄漏路径和上游信息。合理方案是领域异常分类，向客户端返回稳定 `code`、安全 `message` 和 `request_id`，完整堆栈只进入脱敏后的服务端日志。

### 6. 当前 FastAPI 测试覆盖到了什么，没覆盖什么？

**标准回答：**

现有两个测试 monkeypatch 查询函数后直接调用 `perform_query()`，主要保护有无 Trace 时的响应结构。它们没有经过真实 ASGI/HTTP 参数解析，没有覆盖 422、错误映射、其他三个接口、认证、超时和并发。测试还会在 monkeypatch 前导入 `main.py`，触发真实组件初始化。后续应把资源创建移入 lifespan 和依赖注入，再增加 TestClient、依赖 Stub、集成测试及并发测试。

**诚实边界：**本次当前工作区测试在导入初始化阶段未于合理时间内完成，已主动终止，不能称为通过或失败。

## 二、面试前十分钟速记

1. 同步 `def` 路由在线程池运行，但不代表端到端异步或无限并发。
2. `/load-files/` 接收后端路径，不是浏览器文件字节。
3. 配置切换只改进程内全局状态，多 worker 不会自动同步。
4. 参数校验错误可由框架返回 422，业务故障不应全部包装成 500。
