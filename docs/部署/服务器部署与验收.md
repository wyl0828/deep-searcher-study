日期：2026-08-15
适用范围：阿里云 ECS 完整拓扑部署与验收。

## 一、部署边界

服务器现状：

- 4 核 CPU、16 GiB 内存、40 GB 系统盘（可用约 28 GB）、无 Swap；
- 已运行 Nginx（80）、MySQL（3306）、Redis（6379）、Java AI Study 后端（8080）、
  Next.js（4000）、piston_api（2238）。

约束：

- 项目部署到 `/opt/deepsearcher-study`；
- 中间件不暴露公网端口；项目仅 API 绑定服务器回环地址（127.0.0.1:18700 / 18701，
  引擎诊断 18702）；
- 不占用既有 80、3306、6379、8080、2238、4000；
- 项目容器使用独立 Docker 网络（`deepsearcher-study_deepsearcher`）；
- 第一轮不修改 Nginx、不开放安全组；完整内部验收通过后才接入 Nginx；
- Provider 密钥只放服务器 `/opt/deepsearcher-study/.env.server`，不进入 Git 与镜像；
- 不推送代码、不移动现有标签。

注：2026-08-15 经用户授权关闭原有 AI Study 业务服务（backend/frontend/mysql/redis/
piston_api），nginx 保留运行；恢复脚本见 `/opt/deepsearcher-study/backups/
restore-existing-services.sh`。

## 三、阶段一：本地部署文件

新增文件：

- `compose.server.yaml`：与 `compose.yaml` 叠加的服务器覆盖。只把 Core API 与两个产品
  API 绑定 `127.0.0.1`；PostgreSQL、Redis、MinIO、RocketMQ、etcd、Milvus 不发布端口；
  每个常驻容器配置 json-file 日志轮转（10 MB × 3）与 CPU 限制；内存限制沿用
  `compose.yaml` 的 `mem_limit`；Consumer 使用进程存活探针作为健康检查；一次性初始化/
  迁移任务以退出码 0 表示完成。
- `.env.server.example`：服务器私有环境模板，复制为 `.env.server` 后修改。
- `deploy/server/deploy.ps1`：本地打包 + SCP 上传 + 服务器准备/构建/分组启停。
- `deploy/server/status.ps1`：状态查看（容器、资源、磁盘、日志体积）。
- `deploy/server/smoke.ps1`：回环健康检查冒烟。
- `deploy/nginx/deepsearcher.conf.example`：Nginx 反向代理模板（SSE、上传、超时）。
- 本文档。

本地校验：

```powershell

uv run --frozen pytest tests/test_compose_contract.py -q
```

## 四、阶段二：服务器基础准备

1. 安装 Docker Compose 插件（不重启 Docker，不影响既有容器）：
   ```bash
   apt-get update && apt-get install -y docker-compose-plugin
   docker compose version
   ```
2. 创建目录：
   ```bash
   mkdir -p /opt/deepsearcher-study/releases \
            /opt/deepsearcher-study/shared \
            /opt/deepsearcher-study/backups
   ```
3. 部署以 root 执行，容器内应用以非 root（镜像默认用户）运行；数据卷由容器内部属主
   初始化（RocketMQ 使用一次性 chown 任务）。
4. 检查 Docker 存储与剩余磁盘；不修改 Docker 全局日志配置，日志轮转由项目 Compose
   单独配置（`compose.server.yaml`），避免重启 Docker 影响既有容器。
5. 创建 2~4 GB Swap（可降内存峰值，占用 2~4 GB 磁盘）：
   ```bash
   fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
   echo '/swapfile none swap sw 0 0' >> /etc/fstab
   ```

验收：`docker compose version` 可用；nginx 与既有基础设施未受影响。

## 五、阶段三：传输与构建

```powershell
.\deploy\server\deploy.ps1 -Action deploy -Release 20260815-01
```

该动作依次执行：

- `package`：从已验证提交 `git archive` 生成干净 tar.gz（自动排除 `.git`、`.env`、
  测试缓存、本地数据库、临时文件、`node_modules`、模型缓存、密钥等未跟踪内容）；
- `upload`：SCP 上传并解压到 `/opt/deepsearcher-study/releases/20260815-01`；
- `prepare`：生成私有 `/opt/deepsearcher-study/.env.server`（随机密钥，Provider 密钥
  可经 `-ProviderEnvFile` 合并或手工填写），只输出键名与长度，不输出密钥值；
- `build`：构建应用镜像，构建后清理无用构建缓存，记录构建前后磁盘容量；
  剩余空间低于 10 GB 时停止后续部署。

验收：镜像构建成功；密钥未进入镜像与部署包；既有容器未受影响。

## 六、阶段四：分组启动与验证

按资源依赖逐组启动，任一分组失败即停在当前阶段排查，不启动应用层。

```powershell
.\deploy\server\deploy.ps1 -Action start -Group storage
.\deploy\server\deploy.ps1 -Action start -Group vector
.\deploy\server\deploy.ps1 -Action start -Group messaging
```

验证要点：

- Storage：PostgreSQL/Redis/MinIO 健康；PostgreSQL 空库 Alembic 升级；MinIO 对象
  写入/读取/删除；Redis 摘要锁互斥与超时恢复。
- Vector：etcd/Milvus 健康；创建测试集合、写入/查询/删除向量；重启后数据仍存在。
- Messaging：Transaction Topic 存在；Half Message Commit/Rollback/事务回查通过；
  ACK、未 ACK 重试与最终失败行为通过。

## 七、阶段五：应用部署

```powershell
.\deploy\server\deploy.ps1 -Action start -Group app
.\deploy\server\smoke.ps1
```

实例规划：

| 实例       | 绑定                      | 说明                        |
| ---------- | ------------------------- | --------------------------- |
| API A      | 127.0.0.1:18700 -> 8700   | 产品 API A                  |
| API B      | 127.0.0.1:18701 -> 8700   | 产品 API B                  |
| Consumer A | 无宿主机端口              | RocketMQ 入库消费           |
| Consumer B | 无宿主机端口              | RocketMQ 入库消费           |
| Core API   | 127.0.0.1:18702 -> 8000   | 引擎（诊断端口，仅回环）    |

摘要功能启用共享 Redis 锁（`DEEPSEARCHER_SUMMARY_LOCK=redis`）。

验收：两个 API 均健康；两个 Consumer 能消费；API A 创建的数据 API B 可访问；应用不自动
修改 PostgreSQL Schema（仅 Alembic 升级）；所有容器总内存处于安全范围。

## 八、阶段六：完整业务验收

真实链路：API A 上传 PDF → MinIO 保存对象 → Document 创建 → RocketMQ 事务消息 →
Consumer B 处理（解析、分块、Embedding）→ Milvus 写入 → API B 查询 → 返回回答与引用 →
API B 预览原文。

验证：文档状态迁移正确；同一任务无并发重复处理；Manifest 有效；引用可定位到原文；
Trust 结果存在；对象、数据库与向量数据一致；重复消息不破坏已完成状态。

## 九、阶段七：故障恢复验收

1. 停止 API A，API B 继续服务；恢复 API A，共享状态一致；
2. 停止 Consumer A，Consumer B 继续消费或接管重试；
3. 长耗时消费验证 ACK 与重试；
4. 同一会话并发触发摘要只产生一份有效摘要；
5. 重启 2 API + 2 Consumer；重启项目中间件容器；
6. 再次查询、预览并检查引用。

只操作本项目容器，不重启服务器。

## 十、阶段八：Nginx 接入

完整内部验收通过后执行。备份配置 → `nginx -t` → 通过后 reload；失败则恢复。

配置要点（见 `deploy/nginx/deepsearcher.conf.example`）：

- 新路径/独立域名反向代理到 API A（主）+ API B（backup）；
- `proxy_buffering off` 等关闭 SSE 缓冲；
- `client_max_body_size 200m` 增大上传限制；
- 长请求超时（`proxy_read_timeout 3600s`）。

数据库与中间件仍不开放公网。

## 十一、阶段九：观察（2~4 小时）

持续记录：容器状态与重启次数、CPU/内存/Swap、磁盘剩余、日志增长、消息堆积与重复消费、
文档处理耗时、摘要数量、PostgreSQL/MinIO/Milvus 持久化。

停止条件：剩余磁盘 < 10 GB；可用内存持续 < 1 GB；出现 OOM；影响服务器已有业务；
中间件反复重启。

## 十二、一键启停与状态检查

```powershell
# 启动完整拓扑（服务器）
.\deploy\server\deploy.ps1 -Action start -Group full

# 停止（保留容器）
.\deploy\server\deploy.ps1 -Action stop -Group full

# 移除项目容器与网络（保留命名卷）
.\deploy\server\deploy.ps1 -Action down

# 状态与冒烟
.\deploy\server\status.ps1
.\deploy\server\smoke.ps1

# 查看日志
.\deploy\server\deploy.ps1 -Action logs -Group app
```
