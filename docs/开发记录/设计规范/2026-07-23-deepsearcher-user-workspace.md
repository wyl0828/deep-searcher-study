# DeepSearcher 用户工作台 P0 产品需求与交互规格

> 日期：2026-07-23  
> 状态：已确认产品边界，待实施  
> 视觉基准：`docs/设计参考/2026-07-23-deepsearcher-user-workspace.png`

## 1. 产品目标

将当前面向学习和调试的中文控制台扩展为普通用户可以直接使用的私有知识库问答产品。P0 必须让用户在不理解 RAG、Embedding、Milvus 或 Agent Trace 的情况下完成以下闭环：

```text
创建知识库 → 上传 PDF → 等待处理完成 → 发起问题
→ 阅读带引用的答案 → 核对原文证据 → 继续追问
```

现有学习控制台继续保留，用于开发、教学和故障诊断，但不再作为默认产品首页。

## 2. P0 边界

### 2.1 包含

- 本地单用户使用，不要求登录。
- 桌面 Web 为主要使用场景。
- PDF 是首个正式支持的文档格式。
- 支持创建、选择和查看知识库。
- 支持上传 PDF 并查看真实处理状态。
- 支持新建对话、连续追问和最近对话。
- 回答展示可核对的引用来源。
- 支持证据不足、服务不可用和处理失败等状态。
- 现有学习控制台迁移到 `/console`。

### 2.2 不包含

- 账号、团队、租户和权限体系。
- 分享、协作和公开链接。
- 网页、图片、Office 文档等更多数据源。
- 多模型切换和普通用户可见的模型参数。
- 虚构的逐阶段入库进度或查询思维过程。
- 完整 PDF 在线阅读器。
- 真正的流式 Token 输出；只有后端提供真实事件后才接入。

## 3. 用户概念

| 系统概念 | 用户界面名称 | 说明 |
| --- | --- | --- |
| Collection | 知识库 | 一组可以共同检索的资料 |
| File | 文档 | 用户上传的一份 PDF |
| Query Session | 对话 | 围绕同一上下文进行的连续问答 |
| Retrieval Result | 引用来源 | 支撑回答的原文片段 |
| Trace | 高级详情 | 仅开发入口可见的执行信息 |
| Ingestion | 文档处理 | PDF 解析、切分、向量化和写入 |

普通用户界面不得默认出现 Milvus、Embedding、`max_iter`、Token、Agent、Collection Router 或 Chain of RAG 等术语。

## 4. 信息架构

| 页面 | 路径 | P0 职责 |
| --- | --- | --- |
| 新对话 | `/` | 空状态、选择知识库、输入第一个问题 |
| 对话详情 | `/chat/:conversationId` | 展示问答、引用和继续追问 |
| 知识库列表 | `/knowledge` | 创建、选择和浏览知识库 |
| 知识库详情 | `/knowledge/:knowledgeBaseId` | 上传和管理当前知识库的 PDF |
| 学习控制台 | `/console` | 承载当前开发与学习界面 |

以下内容使用覆盖层完成，不创建独立路由：

- 知识库选择器。
- 创建知识库弹窗。
- 上传文档弹窗。
- 引用来源抽屉。
- 删除确认弹窗。

## 5. 全局应用框架

### 5.1 左侧导航

桌面端固定宽度约 240～280px，包含：

1. DeepSearcher Logo 和产品名。
2. 主操作“新建对话”。
3. 一级导航“对话”“知识库”。
4. 当前知识库快捷入口。
5. 按“今天”“最近 7 天”分组的最近对话。
6. “查看全部对话”入口。
7. 底部用户菜单；P0 只包含设置占位和“学习控制台”入口。

行为要求：

- “新建对话”始终可见。
- 点击历史对话后，当前项高亮并进入对应 URL。
- 对话标题超过一行时截断，鼠标悬停可查看完整标题。
- 用户进行中的输入不能因为切换引用抽屉而丢失。

### 5.2 顶部栏

问答区顶部只展示：

- 当前知识库名称和切换入口。
- 全局搜索占位入口，P0 可以不实现搜索，但不得伪装为可用输入框。
- 收起/展开引用抽屉的控制。

页面不展示服务状态、模型名称和本次 Token。

## 6. 页面级规格

## 6.1 新对话页 `/`

### 目标

让用户明确当前会检索哪个知识库，并尽快提出第一个问题。

### 页面内容

- 当前知识库选择器。
- 标题“向你的资料提问”。
- 一句话说明：“答案会优先依据当前知识库，并附上可核对的来源。”
- 多行问题输入框。
- 附件入口；P0 点击后进入当前知识库的上传弹窗。
- 发送按钮。
- 2～3 个基于产品能力的通用建议问题，不伪装成根据文档实时生成。

### 关键状态

#### 没有知识库

- 主标题：“先创建一个知识库”。
- 说明：“上传 PDF 后，就可以基于自己的资料提问。”
- 主按钮：“创建知识库”。
- 问题输入框禁用。

#### 知识库没有可用文档

- 主标题：“为这个知识库添加资料”。
- 主按钮：“上传 PDF”。
- 次操作：“切换知识库”。
- 输入框保留但发送按钮禁用，并解释原因。

#### 可以提问

- 输入框可编辑。
- `Enter` 发送，`Shift + Enter` 换行。
- 去除首尾空白后问题不能为空。
- 请求期间禁止重复发送，但允许复制已输入内容。

## 6.2 对话详情页 `/chat/:conversationId`

### 目标

让用户获得清晰答案、核对证据并自然继续追问。

### 页面结构

1. 用户问题。
2. DeepSearcher 回答。
3. 回答操作区。
4. 底部固定追问输入框。
5. 右侧引用来源抽屉。

### 回答展示

- 使用正文布局，不使用大面积聊天气泡。
- 支持段落、标题、列表、代码块和行内代码。
- 正文推荐宽度不超过约 760px。
- 引用使用 `[1]`、`[2]` 形式，紧跟相关结论。
- 点击引用编号打开右侧来源抽屉并选中对应来源。
- 不展示相似度分数给普通用户。

### 回答操作

- 复制。
- 重新生成。
- 有帮助。
- 没帮助。

P0 的反馈可以只保存在本地业务数据库，不要求分析后台。

### 查询状态

| 状态 | 用户反馈 |
| --- | --- |
| `submitting` | 保留用户问题，回答区显示“正在检索资料并生成答案…” |
| `success` | 展示答案、引用和继续追问输入框 |
| `insufficient_evidence` | 明确说明当前资料没有足够依据，并建议换一种问法或上传资料 |
| `error` | 保留问题，展示安全错误摘要和“重新尝试” |

当前后端不能提供实时阶段时，只显示统一等待状态，不逐步播放“检索完成”“正在反思”等伪进度。

### 连续追问边界

P0 保存完整对话供页面展示，但当前 DeepSearcher 查询接口仍是单问题调用。若后端尚未把历史消息纳入检索或生成，界面不得暗示模型已经理解完整上下文；实施时必须选择以下一种真实行为：

1. 在服务端将必要历史整理进下一次查询；或
2. 将追问改写成独立完整问题后再查询，并在产品说明中明确。

## 6.3 知识库列表页 `/knowledge`

### 目标

让用户创建和选择资料范围，而不是管理向量数据库。

### 页面内容

- 页面标题“知识库”。
- 主按钮“创建知识库”。
- 知识库列表。
- 每项展示名称、描述、文档总数、可用文档数和更新时间。
- 空状态引导创建第一个知识库。

### 创建知识库

字段：

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填，1～40 个可见字符 |
| 描述 | 可选，最多 200 个字符 |

名称可以使用中文。系统负责生成内部安全标识，不要求用户填写 Milvus Collection 名称。

### P0 操作

- 创建。
- 进入详情。
- 设为当前知识库。

删除整个知识库属于高风险操作，P0 可以暂不开放；若开放，必须显示文档数量并进行二次确认。

## 6.4 知识库详情页 `/knowledge/:knowledgeBaseId`

### 目标

让用户清楚知道哪些资料已经可以被问答使用。

### 页面内容

- 知识库名称、描述和当前状态。
- 主按钮“上传 PDF”。
- 文档列表。
- 每个文档展示文件名、大小、添加时间和处理状态。

### 文档状态

| 状态 | 界面文案 | 可用操作 |
| --- | --- | --- |
| `queued` | 等待处理 | 删除 |
| `processing` | 正在处理 | 无重复提交 |
| `ready` | 可用于问答 | 查看来源信息、删除 |
| `failed` | 处理失败 | 重试、删除 |

只有 `ready` 文档可以进入查询范围。

### 上传规则

- P0 仅接受 PDF。
- 单文件最大 20 MiB，与当前本地代理限制保持一致。
- 浏览器和服务端都必须校验扩展名、MIME、空文件和 PDF 文件头。
- 相同文件名不得直接覆盖已有文档；提示用户取消或作为新版本添加。
- 上传成功不等于处理完成。

### 删除规则

- 删除前二次确认。
- 文档从产品数据库删除后，对应向量数据也必须清理；在无法保证精确删除前，P0 不应开放单文档删除。
- 若当前向量适配层只能删除整个集合，实施时先把删除标为 P1，不能只删列表记录而遗留向量。

## 6.5 引用来源抽屉

### 目标

帮助用户核对答案是否真正来自自己的资料。

### 内容

- 标题“引用来源 N”。
- 回答中引用编号与来源一一对应。
- 文件名。
- 页码或章节；后端未提供时不显示占位数字。
- 原文片段。
- “查看原文”入口；P0 没有原文定位能力时隐藏。

### 数据规则

- 一个回答中的重复来源应合并。
- 优先展示被支持过滤确认的片段。
- 原文片段为空时显示“该来源暂时无法预览”，但保留文件名。
- 不把内部文件绝对路径、查询参数、API Key 或完整模型响应暴露给浏览器。

当前 `TraceCollector` 已能安全返回文件引用、截断文本、分数和 `supported` 标记，但没有稳定 `document_id`、页码和切片编号。P0 引用接口必须补充这些字段；未补充前只能展示后端真实返回的文件名和片段。

## 6.6 学习控制台 `/console`

现有控制台整体迁移到该路径，继续用于：

- PDF 入库学习。
- RAG 查询过程观察。
- 服务与模型配置摘要。
- 结构化 Trace 和事件日志。

普通用户主导航不直接展示技术入口。P0 可在左下用户菜单中提供“学习控制台”链接。

## 7. 关键交互流程

## 7.1 首次使用

```text
访问 /
→ 检测到没有知识库
→ 点击“创建知识库”
→ 输入名称并创建
→ 打开上传弹窗
→ 选择 PDF 并通过校验
→ 返回知识库详情，状态为“正在处理”
→ 处理完成后显示“可用于问答”
→ 点击“开始提问”
→ 输入问题
→ 展示答案和引用
→ 点击 [1] 打开来源抽屉
```

## 7.2 日常问答

```text
选择知识库
→ 新建对话
→ 输入问题
→ 提交并等待真实结果
→ 阅读答案
→ 点击引用核对来源
→ 输入追问
→ 对话自动保存
```

## 7.3 文档处理失败

```text
上传 PDF
→ 服务端处理失败
→ 文档记录保留为“处理失败”
→ 展示安全失败原因
→ 用户重试或删除
```

## 7.4 证据不足

```text
查询完成但没有可靠支持片段
→ 不生成看似确定的无来源结论
→ 展示“当前资料中没有找到足够依据”
→ 建议换一种问法、切换知识库或上传相关资料
```

## 8. 错误与反馈文案

| 场景 | 推荐文案 |
| --- | --- |
| 后端不可用 | “问答服务暂时不可用，请稍后重试。” |
| 向量库不可用 | “知识库暂时无法访问，请稍后重试。” |
| 非 PDF | “目前仅支持上传 PDF 文件。” |
| 文件过大 | “PDF 文件不能超过 20 MiB。” |
| 文件为空或无效 | “所选文件不是有效的 PDF。” |
| 查询为空 | “请输入你想了解的问题。” |
| 文档未就绪 | “资料仍在处理中，完成后即可提问。” |
| 无可靠来源 | “当前资料中没有找到足够依据。” |
| 未知错误 | “操作没有完成，请重新尝试。” |

错误响应不得直接展示后端堆栈、本地绝对路径或第三方密钥信息。

## 9. 响应式与可访问性

P0 以 1440 × 1024 设计稿为视觉基准，同时满足：

- 1024px 以上保持三栏结构。
- 768～1023px 时隐藏左侧栏为抽屉，引用抽屉覆盖在右侧。
- 低于 768px 时允许基础问答，但完整移动端优化列入 P1。
- 交互控件可使用键盘访问，并有清晰的焦点状态。
- 图标按钮提供可访问名称。
- 正文和控件文字满足基本对比度。
- 不仅依赖颜色表达文档成功或失败。

## 10. P0 验收标准

1. 新用户可以从没有知识库开始，完成创建、上传、提问和引用核对。
2. 已有用户可以切换知识库、新建对话并找回最近对话。
3. 查询期间不展示后端没有提供的虚假阶段。
4. 每个引用都能映射到后端真实返回的来源片段。
5. 页码缺失时界面不会生成示例页码。
6. 文档上传成功与处理完成有明确区别。
7. 服务离线、无证据、无文档和处理失败时页面不会崩溃。
8. 用户输入在失败后仍然保留。
9. 普通用户页面不暴露 Milvus、Embedding、Token、`max_iter` 和 Trace。
10. 现有学习控制台可通过 `/console` 使用。

## 11. 产品风险和前置依赖

- 当前查询接口没有显式知识库范围参数，用户选择知识库后无法保证只检索该知识库；这是 P0 阻塞项。
- 当前入库接口同步返回，无法表示排队、处理中和失败重试；需要任务状态模型。
- 当前系统没有知识库、文档、任务、会话和消息的产品数据存储。
- 当前 Trace 来源缺少稳定文档 ID、页码和切片 ID，无法实现完整引用定位。
- 当前向量数据库抽象层没有统一的单文档删除能力，文档删除可能需要延后。
- 当前连续追问没有明确的历史上下文注入策略，不能仅靠前端历史列表声称支持上下文对话。

这些能力未补齐前，界面必须选择诚实降级，不能使用模拟数据掩盖后端缺口。
