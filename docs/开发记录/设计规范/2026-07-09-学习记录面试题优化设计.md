# 第 1～7 天学习记录面试题优化设计

## 目标

以 `docs/学习计划/网上简历与面经材料整理.md` 为追问来源，优化第 1～7 天学习记录中的面试题和参考答案。最终内容既要让初学者读得懂，也要经得住面试官从原理、工程取舍、故障定位和验证方法四个方向连续追问。

网上材料只用于发现问题和学习表达结构。项目答案必须来自 DeepSearcher 当前源码、测试或已经完成的本地实验，不能把网上项目经历、技术方案和量化指标写成当前项目已经实现的能力。

## 采用方案

采用“少而完整”的方案：每一天保留 3～5 道与当天主题直接相关的核心题，不追求把网上题库全部塞入七天。

每道核心题统一使用以下结构：

1. **面试官的人话问题**：先问业务、原理或取舍，不以英文类名开头。
2. **一句话回答**：先给明确结论。
3. **2～3 分钟深入回答**：说明是什么、为什么、怎么做和代价。
4. **连续追问**：列出面试官可能沿着答案继续追问的 2～3 个问题。
5. **项目证据**：给出真实源码、测试或实验，不要求第一遍背路径。
6. **诚实边界**：明确当前项目没有实现、没有评测或尚未验证的部分。

## 七天问题分配

### 第 1 天：项目跑通与故障定位

- 为什么先建立可复现基线？
- 页面没有结果时，怎样区分前端、后端、模型和向量库故障？
- 为什么浏览器不能直接调用模型和 Milvus？
- 如何证明项目真的跑通，而不是页面能打开？

重点引入网上材料中的可靠性思路：链路分层、超时、错误分类、可观测性。暂不宣称已经实现熔断、自动重试或人工兜底。

### 第 2 天：配置、工厂和共享状态

- 为什么要配置化切换模型和组件？
- 动态工厂与直接实例化如何选择？
- 全局配置为什么方便，又为什么不适合并发和多租户？
- 如何避免 API Key 和配置泄漏？

重点追问配置校验、运行时错误、依赖注入、多 worker 和租户隔离。

### 第 3 天：文档解析与切分

- 为什么不能整篇 PDF 直接向量化？
- 切分大小与重叠如何确定，如何用评测而不是经验拍值？
- 扫描件、表格、多栏和图片为什么可能解析失败？
- 如何提供页码或章节级引用？

重点引入 Recall@K、上下文完整性、成本和引用精度，但明确当前项目没有系统切分评测。

### 第 4 天：Embedding 与距离度量

- Embedding 解决什么问题，又不能解决什么问题？
- 为什么入库和查询的向量维度必须一致？
- L2、Cosine 和 IP 如何选择，为什么不能混淆距离与相似度？
- 切换 Embedding 模型为什么通常需要重建知识库？

重点追问向量归一化、离线对比实验和模型迁移。

### 第 5 天：Milvus 与检索故障

- 为什么选择向量数据库，Milvus、FAISS、pgvector 如何取舍？
- Milvus Lite 与 Docker Milvus 分别适合什么阶段？
- 空结果为什么不一定代表知识库没有答案？
- Collection、索引、距离度量和维度之间是什么关系？
- 如果检索流量扩大十倍，首先改什么？

扩容题只给设计方向，不包装成当前项目已经具备的生产能力。

### 第 6 天：离线入库综合表达

- 用一分钟讲清知识如何进入系统。
- 如何判断答案差是解析、切分、向量模型还是检索的问题？
- 如何设计一套最小离线检索评测？
- 当前离线入库最大的三个技术债是什么？

重点把前五天从“知识点”串成“可诊断、可验证的工程链路”。

### 第 7 天：在线查询、路由与朴素 RAG

- 为什么不用一次朴素 RAG 解决所有问题？
- 为什么使用 LLM 路由，非法输出如何处理？
- Collection 路由失败为什么可能伪装成无命中？
- 如何区分检索失败和生成失败？
- Trace 为什么不是模型思维链？

重点引入 Agent 可靠性、停止条件、路由评测和 Token 成本；DeepSearch 的具体迭代算法留到后续学习日。

## 写作规则

- 标题和问题优先使用中文业务语言，英文类名只在括号或项目证据中出现。
- 回答先给因果关系，再给源码路径，避免把源码调用顺序当成解释。
- 每个答案至少包含一个取舍或失败场景。
- 没有真实指标时，写清“应该如何测”，不编造提升百分比。
- 不把计划能力写成已实现能力。
- 同一天的问题避免重复；第 6 天负责综合，第 1～5 天负责单点原理。
- 每天末尾增加“不看答案模拟追问”，检验能否脱离源码名进行表达。

## 验收方式

1. 第 1～7 天每篇都有 3～5 道结构完整的核心题。
2. 抽查任意 10 题，均有结论、因果、取舍、项目证据和诚实边界。
3. 问题标题不以难懂的英文类名作为理解入口。
4. 网上材料中的可疑指标和未实现方案没有被写成项目成果。
5. Markdown 围栏和标题层级完整，MkDocs 能成功构建。

## 不在本次范围

- 不修改 DeepSearcher 业务代码、接口、模型配置或测试逻辑。
- 不补写第 8 天及之后的学习记录。
- 不把 Java/JUC/JVM/MySQL 八股题混入当前 Python AI 全栈学习记录。
- 不制作简历成稿；简历表达将在完成更多真实实验后单独整理。
