# 第 1～7 天学习记录面试题优化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 根据网上简历与面经材料，重写第 1～7 天学习记录的核心面试题，使每道题兼具人话表达、深入回答、连续追问、项目证据和诚实边界。

**Architecture:** 七篇学习记录仍各自负责当天主题，不新建独立答案库。每篇将原有面试题区域整理为 3～5 道结构统一的核心题，并在文末补充脱离源码名的模拟追问；网上材料只提供追问方向，答案继续以本仓库源码、测试和已完成实验为依据。

**Tech Stack:** Markdown、MkDocs、PowerShell、ripgrep

---

## 文件结构

- 修改 `docs/学习计划/第1天学习记录.md`：项目基线、全栈链路与故障定位。
- 修改 `docs/学习计划/第2天学习记录.md`：配置工厂、共享状态与密钥边界。
- 修改 `docs/学习计划/第3天学习记录.md`：解析、切分、引用与检索评测。
- 修改 `docs/学习计划/第4天学习记录.md`：Embedding、维度、距离度量与模型迁移。
- 修改 `docs/学习计划/第5天学习记录.md`：Milvus 选型、部署路径、空结果和扩容。
- 修改 `docs/学习计划/第6天学习记录.md`：离线入库综合诊断、评测和技术债。
- 修改 `docs/学习计划/第7天学习记录.md`：在线路由、朴素 RAG、错误分类和 Trace。
- 不修改业务代码、接口、配置、测试文件和 MkDocs 导航。

### Task 2：改写第 1～2 天

- [ ] **Step 1：改写第 1 天核心题**

1. 为什么先建立可复现基线？
2. 页面没有结果时怎样逐层定位？
3. 为什么浏览器不能直接调用模型和向量库？
4. 如何证明全链路真的跑通？

每题必须出现以下小标题：

```markdown
#### 一句话回答
#### 2～3 分钟回答
#### 面试官继续追问
#### 当前项目证据
#### 诚实边界
```

- [ ] **Step 2：改写第 2 天核心题**

在 `docs/学习计划/第2天学习记录.md` 中整理为四题：

1. 为什么要把模型和组件做成可配置？
2. 动态工厂和直接实例化如何选择？
3. 全局配置为什么不适合并发和多租户？
4. 如何避免 API Key 和配置泄漏？

证据至少覆盖 `configuration.py`、`ModuleFactory`、`init_config` 和当前模块级全局对象；安全题不得声称当前项目已经实现密钥托管或租户隔离。

### Task 4：改写第 6～7 天

### Task 5：自动审查和构建验证

- [ ] **Step 1：检查七篇统一结构和题目数量**

运行：

```powershell
1..7 | ForEach-Object {
  $path = "docs/学习计划/第$($_)天学习记录.md"
  $text = Get-Content -Raw -LiteralPath $path
  $questionCount = ([regex]::Matches($text, '(?m)^### 核心题 \d+：')).Count
  if ($questionCount -lt 3 -or $questionCount -gt 5) {
    throw "第 $_ 天核心题数量不合格：$questionCount"

}
```
