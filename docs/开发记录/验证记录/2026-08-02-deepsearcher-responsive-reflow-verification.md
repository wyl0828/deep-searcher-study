# DeepSearcher 工作台响应式回流验证

日期：2026-08-02

范围：移动端历史对话首屏、引用抽屉、知识库详情标题与操作区、顶部导航，以及 `320px`、
`390px`、`640px` 等效内容宽度下的横向回流。

## 1. 已修复问题

- 历史对话原先默认打开引用来源。桌面端这是侧栏，但 `820px` 以下会变成覆盖约 `92vw` 的固定层，
  导致用户进入移动端对话后无法先阅读回答。
- 移动端引用层仍是普通 `aside`，没有遮罩、模态名称、焦点闭环或背景滚动锁定。
- 知识库标题和“当前知识库”标签横排时会压缩中文标题，形成孤字换行。
- 脚手架的 `body { min-width: 320px; }` 在 Windows 纵向滚动条存在时会产生额外横向滚动；极窄
  页头导航、顶部工具栏和知识库操作区也会发生溢出或文字被挤成竖排。

## 2. 实现契约

- `useMediaQuery("(max-width: 820px)")` 把组件行为与 CSS 断点统一：桌面引用栏默认展开，移动端
  进入或切换对话时默认关闭。
- 移动端引用来源按需打开后使用 `role="dialog"`、`aria-modal="true"` 和标题关联；复用
  `useModalFocus` 管理初始焦点、Tab 闭环、Esc 与触发点恢复，并在打开期间锁定 `body` 滚动。
- 遮罩拦截背景点击；抽屉使用 `100dvh` 适配移动浏览器动态工具栏，同时保留 `100vh` 回退。
- `560px` 以下标题与状态纵向排列，顶部工具栏保持“知识库名称 + 引用按钮”双列并截断长名称；
  `360px` 以下收紧页头导航，知识库危险操作、设为当前和上传按钮改为纵向全宽排列。
- 全局页面不再强制 `320px` 最小宽度；旧学习控制台自己的宽布局约束仍由 `.app-shell` 负责。

## 4. 真实浏览器验证

- `390px`：历史对话先显示回答，引用抽屉默认不存在，文档宽度与滚动宽度一致。打开后抽屉具有
  `dialog`/`aria-modal` 语义、遮罩和滚动锁定，焦点位于“关闭引用来源”；Esc 关闭后焦点回到
  “切换引用来源”。
- `390px` 知识库详情：标题与状态按列回流，不再由状态标签把标题挤出孤字；顶部引用按钮保持在
  64px 工具栏内。
- `320px` 外层视口（Windows 内容宽度 `305px`）：首页、知识库详情和对话页的 `scrollWidth`
  均等于 `clientWidth`；首页输入区和建议问题宽度为 `268.67px`，知识库三项操作同宽纵向排列。
- `320px` 对话页：回答区域宽 `268.67px`，引用抽屉默认关闭；按需打开后宽 `294.40px`、右边界
  与视口一致，未产生额外横向溢出。
- `640px` 等效内容宽度：对话与知识库详情均回流到移动布局，内容宽度 `625px` 时滚动宽度同为
  `625px`。

验证过程未创建、修改或删除业务数据。本记录证明上述断点与键盘基础契约，不等同于完整 WCAG
合规；真实浏览器缩放菜单、屏幕阅读器浏览模式、触控手势和颜色对比仍应作为独立专项验证。
