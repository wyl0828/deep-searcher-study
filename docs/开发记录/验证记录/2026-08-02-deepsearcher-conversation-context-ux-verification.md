# DeepSearcher 对话知识库上下文与恢复入口验证

日期：2026-08-02

范围：用户工作台首页、知识库详情、历史回答/引用，以及旧索引恢复流程。

## 1. 截图审计结论

本轮在 `1280 × 720` 的真实工作台中只执行只读导航，依次捕获并人工检查：

1. 首页 / 新对话：提问是明确主任务，知识库、上传、联网搜索和建议问题可发现。
2. 当前知识库详情：文档、关联对话和索引可信状态层级清楚，危险操作与主要操作区分明确。
3. 历史回答与引用：页码、片段和打开原文动作完整，但发现对话绑定“Milvus 端到端验收”时，
   固定顶栏错误显示全局当前的“Milvus 学习资料”。
4. 旧索引恢复：知识库页已经提供清楚的“需要重建索引 / 立即重建”动作，但对话输入区仍显示
   “上传文件”，且无法发送问题时仍可切换联网搜索。

完整截图和逐步 UX/可访问性笔记保存在
`output/product-audit-2026-08-02/audit.md`。

## 2. 修复内容

- 工作台布局根据当前路由解析页面上下文：历史对话优先使用对话详情绑定的知识库，加载早期可
  使用对话摘要兜底；知识库详情使用路由对应知识库，首页才回退到全局当前知识库。
- 顶栏显示上下文知识库，并以“打开知识库：名称”提供明确可访问名称；点击直接进入该知识库
  详情，而不是让用户再次从列表寻找。
- 索引未验证时，输入区工具链接由“上传文件”改为“前往重建”并使用重建图标；联网搜索和
  发送按钮一起禁用，避免出现没有结果出口的可操作控件。
- 保留侧栏全局当前知识库标记，因此“默认新对话使用哪个知识库”和“这段历史对话实际使用
  哪个知识库”可以同时表达，不再混为同一状态。
