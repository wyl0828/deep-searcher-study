# DeepSearcher 工作台键盘可访问性验证

日期：2026-08-02

范围：重复导航跳过、可见焦点、创建知识库弹窗、危险确认弹窗的焦点管理。

## 1. 已修复问题

- 工作台原先没有跳过重复侧栏导航的入口；键盘用户每次进入页面都需要经过品牌、主导航、知识库
  和历史对话后才能到达主要内容。
- 创建知识库和危险确认弹窗虽然有 `aria-modal`，但没有约束 Tab 焦点；创建弹窗也没有 Esc 关闭
  与触发点焦点恢复。
- 工作台不同按钮和链接依赖浏览器默认焦点样式，视觉反馈不统一。

## 2. 实现契约

- 页面第一个可聚焦元素是“跳到主要内容”；获得键盘焦点时才从视口顶部出现，目标为带
  `tabIndex=-1` 的 `main#workspace-main`。
- 新增共享 `useModalFocus`：打开时保存触发点，聚焦显式初始控件；Tab/Shift+Tab 只能在弹窗
  可用控件间循环；Esc 在非 pending 状态关闭；关闭或卸载后恢复原触发点。
- 创建弹窗初始聚焦名称输入框；危险确认弹窗初始聚焦“取消”，避免默认落到不可撤销操作。
- pending 期间创建弹窗的遮罩、关闭按钮、取消按钮和 Esc 同步禁用，避免请求完成前关闭后又发生
  延迟导航。
- 工作台链接和按钮使用统一的高可见焦点环，并保留输入框已有的 `focus-within` 状态。

新增测试覆盖：

- 第一次 Tab 聚焦“跳到主要内容”，且锚点和 main 目标契约正确。
- 创建弹窗打开后名称输入框获得焦点；从首/末控件使用 Shift+Tab/Tab 会在弹窗内循环；Esc 关闭
  后焦点回到“创建知识库”。
- 危险确认弹窗默认聚焦“取消”；焦点在关闭、取消、确认之间闭环；Esc 关闭后回到“删除对话”；
  随后的真实确认删除流程仍正常。

## 4. 真实浏览器验证

在当前生产构建上验证：

- 激活“跳到主要内容”后 URL 变为 `#workspace-main`，活动元素为 `MAIN#workspace-main`。
- 打开创建知识库弹窗后活动元素为名称 `INPUT`；点击关闭后活动元素恢复为带
  `aria-label="创建知识库"` 的原按钮。
- 未创建、修改或删除任何业务数据；浏览器 Console 为 0 warning、0 error。

本记录证明上述键盘基础契约，不代表完整 WCAG 合规。后续仍需独立验证 200%/400% 缩放回流、
屏幕阅读器名称/状态播报和颜色对比。
