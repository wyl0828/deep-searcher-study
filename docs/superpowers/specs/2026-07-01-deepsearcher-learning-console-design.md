# DeepSearcher 中文学习控制台设计

> 日期：2026-07-01  
> 视觉基准：`docs/design-references/2026-07-01-deepsearcher-learning-console.png`

## 1. 目标

构建一个可在本机浏览器使用的中文学习控制台，让用户在完成 PDF 入库与 RAG 问答的同时，看清 DeepSearcher 的离线入库和在线问答两条主流程。

第一版通过现有 FastAPI 调用 DeepSearcher，不修改 Agent、Loader、Embedding 或 Vector DB 核心实现。页面不得把后端未返回的信息伪装成实时 Trace。

## 2. 视觉与布局

桌面端以用户选定的“双泳道画布”为唯一视觉基准，目标视口为 1440 × 1024：

- 顶部使用 DeepSearcher 原始 Logo、产品名“学习控制台”和方案标签。
- 主区域左侧约占 77%，右侧状态栏约占 23%。
- 上半泳道为“离线入库”，展示 PDF 解析、文本切分、Embedding、写入 Milvus。
- 下半泳道为“在线问答”，展示用户问题、查询路由、向量检索、Chain of RAG、最终回答。
- 底部左侧展示最终答案，右侧展示仅包含可观测事件的日志。
- 使用白色背景、深灰文字、青色与靛蓝强调色、绿色成功状态；通过留白、细分隔线和轻边框组织信息。
- 中文采用系统无衬线字体栈，英文和数字优先使用 Inter。图标使用成熟开源图标库，Logo 使用仓库现有资产。

窄屏时右侧状态栏移到主内容下方，泳道节点允许横向滚动，不压缩到不可读。

## 3. 真实交互

### 3.1 服务状态

页面加载时获取本地代理状态：

- FastAPI：检查 `http://127.0.0.1:8500/openapi.json`。
- Milvus：检查 `127.0.0.1:19530` TCP 连接。
- LLM 与 Embedding：读取项目配置并显示模型名称；只标记“已配置”，不冒充在线健康检查。
- Collection 和 `max_iter` 与当前表单状态同步。

### 3.2 PDF 入库

- 用户选择一个 PDF，填写 Collection 名称并点击“开始入库”。
- 浏览器把文件内容发送给同源本地代理；代理保存到临时目录，调用现有 `/load-files/`，无论成功或失败都删除临时文件。
- 仅允许 PDF，文件上限 20 MiB，空文件与非法 Collection 名称在请求前拦截。
- 请求进行中只显示“后台处理中”；FastAPI 没有分阶段进度，因此四个节点不播放伪造的逐步完成动画。
- 成功后显示“入库请求成功”；页数、切片数和向量数显示“API 未提供”，不生成示例数字。

### 3.3 在线问答

- 用户填写问题和 `max_iter`，点击“运行查询”。
- 本地代理调用现有 `/query/`，返回最终答案、总 Token 和前端测得的请求耗时。
- 问答泳道在请求期间显示整体运行状态；完成后标记“流程完成（汇总）”。
- 最终答案支持复制。
- 当前 API 只返回总 Token，因此提示词 Token 和完成 Token 显示“未提供”。

### 3.4 事件日志

日志只记录前端或代理能够确认的事件：请求开始、后端响应成功、后端错误、耗时与总 Token。不得写入虚构的子查询数量、命中片段数量、反思判断或内部 Agent 状态。

## 4. 技术架构

前端是自包含的 React + TypeScript + Vite 子项目，位于 `frontend/`。生产构建由一个轻量 FastAPI 同源代理提供：

```text
浏览器 :8600
  ├─ React 静态资源
  └─ /api/* 本地代理
       ├─ FastAPI :8500
       ├─ Milvus :19530 健康检查
       └─ deepsearcher/config.yaml 只读配置摘要
```

本地代理负责隐藏服务端路径、临时文件和模型配置细节，浏览器不接触 API Key。前端不直接跨域访问 DeepSearcher FastAPI。

## 5. 文件边界

- `frontend/src/App.tsx`：页面组合和交互状态。
- `frontend/src/components/`：泳道、状态栏、表单、结果与日志组件。
- `frontend/src/api.ts`：浏览器端 API 类型与调用。
- `frontend/src/styles.css`：视觉稿对应的布局和响应式规则。
- `frontend/server.py`：静态资源托管、健康检查、PDF 临时上传与 DeepSearcher API 代理。
- `frontend/tests/`：代理的输入校验与响应映射测试。
- `frontend/src/*.test.tsx`：关键中文界面和交互测试。

## 6. 错误处理

- 服务未启动时，状态栏显示离线，表单仍保留输入，操作区给出可理解的中文错误。
- DeepSearcher 返回的错误只展示安全摘要，不泄露 API Key、完整环境变量或本机临时路径。
- 网络超时、非法 JSON、超大文件、非 PDF 和空问题分别给出明确提示。
- 重复提交在请求期间禁用按钮，完成后恢复。

## 7. 验收标准

- 视觉结构、比例、颜色、排版和信息层级与选定截图一致。
- 全部用户可见文案为中文，必要的技术名词保留英文。
- PDF 可以通过界面调用真实 `/load-files/`。
- 问题可以通过界面调用真实 `/query/`，显示答案、总 Token 和耗时。
- 服务离线和请求失败时页面不会崩溃，并给出中文反馈。
- 页面明确声明内部 Trace 不可观测，不展示虚假细节。
- 前端单元测试、代理测试、生产构建和浏览器关键流程通过。
- 1440 × 1024 截图通过与视觉基准的设计 QA，`design-qa.md` 最终结果为 `passed`。

## 8. 本阶段不包含

- 修改 DeepSearcher Agent 以输出结构化 Trace。
- 展示真实子查询、召回片段、反思过程或 Token 分类统计。
- 多文件批量上传、知识库管理、登录权限和远程部署。
- 自动切换 Milvus Docker 与 Milvus Lite。
