# DeepSearcher 用户工作台核心流程审计

日期：2026-08-02

## 审计范围

目标用户希望选择已有知识库、查看文档状态、恢复历史回答并核对引用；本轮使用真实本地数据，
只执行只读导航，不创建、重建或删除资源。审计目标同时覆盖基本可访问性风险，但不宣称完成
WCAG 合规验证。

## 流程步骤

1. 首页 / 新对话 — 健康：良好
   - 证据：[01-home.png](01-home.png)
   - 提问是明确的视觉主任务；知识库、上传、联网搜索和建议问题均能在首屏发现。
   - 搜索和引用按钮处于禁用态但没有说明启用条件，属于轻度可理解性风险。
2. 当前知识库详情 — 健康：良好
   - 证据：[02-knowledge-base.png](02-knowledge-base.png)
   - 文档总数、可用数、关联对话和索引可信状态形成清楚层级；删除与上传使用不同危险等级。
   - 嵌入模型、模型版本、维度和分块参数偏技术化，对学习项目合理，但正式用户版宜折叠到高级信息。
3. 历史回答与引用 — 健康：需修复
   - 证据：[03-answer-citations.png](03-answer-citations.png)
   - 引用编号、页码、片段和打开原文动作完整，失败回答也明确说明“系统失败不等于无资料”。
   - 对话实际绑定“Milvus 端到端验收”，固定顶栏却显示全局当前“Milvus 学习资料”，存在来源
     上下文误导。
   - 索引不可用时输入框禁用，但主要恢复链接仍叫“上传文件”，而已有文档并不缺失；联网搜索也
     仍可切换，形成无效操作。
4. 索引恢复页面 — 健康：良好
   - 证据：[04-recovery.png](04-recovery.png)
   - “需要重建索引—尚未验证—立即重建”的因果和动作清楚，文档状态仍可核对。
   - 对话页应直接使用同样的“前往重建”语言，减少用户自己推断恢复路径。

## 可访问性观察

- 已确认主导航有名称，页面使用层级标题，状态区域有语义，图标按钮和引用关闭按钮有可访问名称。
- 禁用输入框把恢复说明主要放在 placeholder 中；禁用控件通常不能获得键盘焦点，因此需要另有
  可聚焦、可见的恢复链接。
- 截图无法证明颜色对比、缩放回流、完整键盘顺序、屏幕阅读器播报和动态状态通知是否合规，需
  通过后续专项测试确认。

## 本轮优先修复

1. 顶栏显示当前页面/对话实际绑定的知识库，并将点击目标指向该知识库详情。
2. 索引不可用时把“上传文件”改为“前往重建”，使用重建图标，并禁用没有结果出口的联网搜索。
3. 增加组件测试，覆盖历史对话与全局当前知识库不一致的场景，以及恢复入口和禁用态。

## 修复后复核

- 证据：[05-answer-context-fixed.png](05-answer-context-fixed.png)
- 固定顶栏已经显示对话实际绑定的“Milvus 端到端验收”；侧栏仍明确标记全局当前知识库，两种
  上下文不再被同一个标签混淆。
- 禁用输入区提供可聚焦的“前往重建”链接，联网搜索同步禁用；点击顶栏知识库名称会进入正确的
  恢复页面。
- 浏览器 Console 为 0 warning、0 error。
